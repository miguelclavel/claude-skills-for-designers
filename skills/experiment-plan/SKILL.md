# Experiment plan

Write the plan before the test starts, so the result can't be argued into whatever anyone hoped.

## Build the plan

1. **Hypothesis.** "Because we saw [evidence], we believe [change] will cause [behaviour] for [audience]." If there's no evidence yet, say the test is exploratory.
2. **What changes.** Control and variant, one line each. If the idea is really several changes, say so and suggest which to test first, or call it a test of a whole direction.
3. **One primary metric** that decides it (click through rate, completion, leads, revenue per visit).
4. **Two guardrails** that must not get worse (errors, drop off, complaints, refunds).
5. **Audience and traffic split,** and which devices.
6. **Run time and size.** At least one full week, so weekdays and weekends both count. Explain in plain words what the sample size depends on (the current rate, the smallest change worth detecting, the traffic) rather than inventing a number; if the person gives the inputs, calculate it.
7. **Decision rule** for win, lose and flat, decided now.

## Reading a result

When someone shares results: check it ran its full time and reached its sample, look at the guardrails before celebrating the main metric, call a flat result flat, and write down what was learned either way so it can go into the team's regular testing review.

## Output

The plan as a short document with those seven headings. Flag any part you had to assume.
